** App API request logs

Highlight tab-separated App API request logs such as =appapi-requests.txt=.

#+begin_src emacs-lisp
(require 'derived)

(defface appapi-log-status-success-face
  '((t (:inherit success)))
  "Face for successful App API request status codes.")

(defface appapi-log-status-warning-face
  '((t (:inherit warning)))
  "Face for client-error App API request status codes.")

(defface appapi-log-status-error-face
  '((t (:inherit error)))
  "Face for server-error App API request status codes.")

(defun appapi-log-status-face (status)
  "Return a face for numeric HTTP STATUS."
  (cond ((string-prefix-p "2" status) 'appapi-log-status-success-face)
        ((string-prefix-p "4" status) 'appapi-log-status-warning-face)
        ((string-prefix-p "5" status) 'appapi-log-status-error-face)
        (t 'font-lock-constant-face)))

(defconst appapi-log-font-lock-keywords
  `((,(rx line-start
          (group (= 4 digit) "-" (= 2 digit) "-" (= 2 digit)
                 " " (= 2 digit) ":" (= 2 digit) ":" (= 2 digit))
          "\t"
          (group (+ (not (any "\t"))))
          "\t"
          (group (+ (not (any " \t"))))
          "\t"
          (group (+ upper))
          " status="
          (group (group (= 3 digit)))
          " dur="
          (group (group (+ digit)) "ms")
          " ip="
          (group (+ (any digit "."))))
     (1 font-lock-builtin-face)
     (2 font-lock-variable-name-face)
     (3 font-lock-string-face)
     (4 font-lock-keyword-face)
     (5 (appapi-log-status-face (match-string 6)))
     (7 font-lock-type-face)
     (9 font-lock-comment-face)))
  "Font-lock keywords for `appapi-log-mode'.")

(define-derived-mode appapi-log-mode fundamental-mode "AppAPI-Log"
  "Major mode for App API request logs."
  (setq font-lock-defaults '(appapi-log-font-lock-keywords)))

(add-to-list 'auto-mode-alist '("appapi-requests\\.txt\\'" . appapi-log-mode))
#+end_src

** [[https://codeberg.org/pkal/flymake-harper.el][flymake-harper]]

A Flymake backend for [[https://writewithharper.com/][Harper]], a grammar checker that runs entirely locally. It
complements =jinx= below: jinx catches misspelled words, Harper catches grammar,
usage, and style problems across the sentence.

The backend shells out to =harper-cli= (not =harper-ls=), which Home Manager
installs from the =harper= package - see =nix/common.nix= in =home_config=.

Upstream quirk worth knowing: =flymake-harper--options=, the list of Harper
rules, is probed with =harper-cli config= inside =eval-when-compile=. Byte
compilation never evaluates the =defcustom= holding the executable name, so the
probe always fails and the list bakes as nil, whether or not =harper-cli= is on
=PATH=. Linting is unaffected, since the backend never reads that list; the only
casualties are the completion candidates when customizing
=flymake-harper-disable=, and file-local values of it being treated as unsafe.

=flymake-harper-setup= enables =flymake-mode= in the buffer itself, so no separate
hook is needed. Diagnostics are browsable with =M-g f= (=consult-flymake=).

=org-mode= derives from =text-mode=, so Harper runs in Org buffers too, which is
wanted. What is not wanted there are the rules that fire on Org syntax rather
than on prose, collected in =nl/flymake-harper-org-disable=:

- =LongSentences=: Harper is handed the raw buffer with no notion of Org syntax,
  so headings, property drawers, tables, and lists all collapse into one
  enormous "sentence" and every Org Roam note gets a =This sentence is 309 words
  long= diagnostic.
- =ToDoHyphen=: every =TODO= keyword in a heading draws =Hyphenate `to-do`=.
- =Spaces=: fires on the indentation of list continuation lines and source
  blocks, which is by far the loudest rule on a note tree.
- =NumericRangeEnDash=: fires on the =-= in tables, dates, and command-line flags.

Second upstream bug, on top of the =flymake-harper--options= one above:
=flymake-harper-disable= does not work at all. Harper reports the rule name as a
JSON string (="LongSentences"=), and =flymake-harper-sentinel-1= filters it with
=memq= against a list of symbols, which can never match - not even the shipped
default of =(Dashes)=. The advice below re-implements that filter with a string
comparison, which makes =flymake-harper-disable= behave as documented, including
buffer-locally.  The rules above are then disabled in Org buffers only;
everything else Harper checks stays on there.

#+begin_src emacs-lisp
(use-package flymake-harper
  :hook (text-mode . nl/flymake-harper-setup)
  :init
  (defvar nl/flymake-harper-org-disable
    '(LongSentences ToDoHyphen Spaces NumericRangeEnDash)
    "Harper rules that fire on Org syntax rather than on prose.")

  (defun nl/flymake-harper-setup ()
    "Set up Harper, dropping rules that misfire on Org markup.
Runs from `text-mode-hook', which precedes `org-mode-hook', so the
disable list is in place before the first check."
    (when (derived-mode-p 'org-mode)
      (setq-local flymake-harper-disable
                  (append nl/flymake-harper-org-disable flymake-harper-disable)))
    (flymake-harper-setup))
  :config
  (defun nl/flymake-harper--apply-disable (args)
    "Drop lints whose rule is in `flymake-harper-disable'.
ARGS are the arguments of `flymake-harper-sentinel-1', (SOURCE DATA).
Upstream compares the rule name, a string, with `memq' against a list of
symbols, so its own filter never matches.  The disable list is read from
SOURCE, since the sentinel runs in the process buffer."
    (pcase-let* ((`(,source ,data) args)
                 (disabled (and (buffer-live-p source)
                                (mapcar (lambda (rule)
                                          (if (symbolp rule) (symbol-name rule) rule))
                                        (buffer-local-value 'flymake-harper-disable source)))))
      (list source
            (if disabled
                (seq-remove (lambda (lint)
                              (member (plist-get lint :rule) disabled))
                            data)
              data))))

  (advice-add 'flymake-harper-sentinel-1 :filter-args
              #'nl/flymake-harper--apply-disable))
#+end_src

** [[https://github.com/mhayashi1120/Emacs-wgrep][wgrep]]

You can edit the text in the grep buffer after typing =C-c C-p=. After that the changed text is
highlighted. The following keybindings are defined:

=C-c C-e=: Apply the changes to file buffers.

=C-c C-u=: All changes are unmarked and ignored.

=C-c C-d=: Mark as delete to current line (including newline).

=C-c C-r=: Remove the changes in the region (these changes are not applied to the files. Of course, the remaining changes can still be applied to the files.)

=C-c C-p=: Toggle read-only area.

=C-c C-k=: Discard all changes and exit.

=C-x C-q=: Exit wgrep mode.

To save all buffers that wgrep has changed, run =M-x wgrep-save-all-buffers=.

#+begin_src emacs-lisp
(use-package wgrep
  :demand t)
#+end_src

      '("~/.emacs.d/snippets"                 ;; personal snippets
        ;;"~/.emacs.d/elpa/yasnippet-snippets-1.0/snippets"
